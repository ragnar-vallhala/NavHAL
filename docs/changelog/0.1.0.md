# 0.1.0 — Foundational Cortex-M4 HAL

**Line:** 0.1.0 → 0.1.2 &nbsp;·&nbsp; **First commit:** 2025-07-18 &nbsp;·&nbsp;
**Target:** STM32F401RE (Nucleo-F401RE), Cortex-M4

The first NavHAL. A single-target hardware abstraction layer for the STM32F401RE,
establishing the `hal_*` driver surface, the register-map layering, the build,
and the in-house test framework. Everything below the platform/multi-arch work
that 0.2.0 later consolidated.

## What's new

### Core peripheral drivers
- **GPIO** — pin configuration and I/O.
- **Clock** — HSI/HSE/PLL system-clock tree, with correct Flash wait-state
  sequencing on up/down transitions.
- **SysTick / Timer** — general-purpose timers with interrupt callbacks
  (TIM2/3/4/5/9), `timer_init_freq` for frequency-based setup.
- **UART** — TX/RX, interrupt-driven RX.
- **PWM** — APB-prescaler-aware duty/frequency, output-compare.
- **I²C** — master transfers; sample drivers for BMP180 / BMX160 sensors.
- **SPI** — master driver.
- **Flash** — key/value store in Flash; correct `.data` copy-from-Flash at boot.

### Advanced drivers
- **DMA** — controller support, integrated as a UART backend.
- **Hardware + software CRC** — `hal_crc_*` with a HW unit and a SW fallback.
- **Hardware FPU** — Cortex-M4 FPU enable + lazy stacking, with a matrix-multiply
  verification sample and `tools/fpu_verify.py`.
- **DWT cycle counter** — high-resolution timing, plus a microsecond-resolution
  timer API on top of `CYCCNT`.
- **SDIO + FatFS** — SD-card init and block I/O, a POSIX-like virtual filesystem,
  file pre-allocation/sync, and a DMA-backed async block path.

### Tooling & tests
- **NavTest** — a custom bare-metal unit-test framework replacing Unity
  (no `setjmp`/libc dependency).
- **`tools/flash.sh`** — build-and-flash helper for samples.
- A broad `samples/` tree (HAL and no-HAL variants) for each driver.

## Patch releases
- **0.1.1 / 0.1.2** — incremental fixes and version bookkeeping along the
  pre-stable development line; superseded when the platform work shipped as
  0.2.0.
