# Public entry points the conformance suite does not call, and why.
# Read by tools/conformance_coverage.py; `symbol: reason`, # starts a comment.
#
# Two kinds of line, and the difference is the point of the file:
#
#   symbol: <reason>        cannot be covered here, and will not be
#   symbol: debt: <note>    could be, is not yet -- delete the line when it is
#
# Neither excuses a NEW entry point: --gate fails on anything in this file
# nor called by the suite, so the surface cannot grow uncovered behind us.
# Being absent from the suite is not being untested -- most of the debt below
# is exercised by its DRV_* cap suite under tests/cap/. What it is missing is
# the portable check that a DIFFERENT port implements it the same way.

# ---------------------------------------------------------------------------
# Cannot be covered: the call ends the run, destroys what the run needs, or
# waits on hardware a bare board does not have.
# ---------------------------------------------------------------------------
hal_system_reset: resets the part, which ends the suite mid-run
hal_flash_erase: erases the sectors holding the KV store and the running image
hal_sdio_wait_flag: spins on a card that a bare board does not have
hal_sdio_wait_sync: spins on a card that a bare board does not have
hal_timebase_tick: the tick ISR's own entry; calling it forges the timebase that the suite's timing cases check against
hal_console_init: re-initialises the transport the suite prints through, at a rate a portable case cannot know; a wrong one garbles the capture
hal_cpu_idle: sleeps until an interrupt arrives, so a suite that calls it on a port whose periodic tick is not running never returns; the Cortex-M4 arch suite covers it against a deliberately pending line
hal_interrupt_clear_all_pending: drops every latched flag on the part, the timebase's own among them -- on the AVR it sweeps TIFR0, which is the tick the suite's timing cases measure against

# Bootloader crypto. CONFIG_BOOT_CRYPTO defaults off, so neither symbol is
# linked into the conformance image, and turning it on would pull one of three
# backends into every target's suite to exercise two functions. They are covered
# where it counts instead: tests/host/test_boot_crypto.c runs all three backends
# against Google Project Wycheproof's EdDSA corpus, and the on-target check is a
# sample rather than a case because a verify is 29 ms on the fastest backend and
# 1.6 s on the slowest.
hal_boot_ed25519_verify: debt: validated on host against the Wycheproof corpus for all three backends; no portable case because CONFIG_BOOT_CRYPTO is off by default
hal_boot_hash: debt: same -- host-validated, and the three backends' SHA-512 outputs are asserted equal there
hal_boot_hash_split: debt: same as hal_boot_hash -- CONFIG_BOOT_CRYPTO is off by default, and tests/host/test_boot_crypto.c asserts the property that matters, that splitting a range equals hashing it whole
